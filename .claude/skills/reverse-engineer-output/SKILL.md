# Reverse Engineer the Output

Source: YouTube video "Reverse Engineer Anything" (creator name not stated in the transcript; UNCLEAR). Core idea from the video: a generic goal gets a generic result, but a set of proven examples works as a ready-made spec.

## Purpose and triggers
Use before creating any repeatable output: a skill, a report (for example a weekly client report), a post style, a landing-page section, an email, a video edit style. Use it when you can point at examples that already work better than you could describe them.

## Inputs checklist
- [ ] 5 or more examples of the output done well. The video's examples range from about 5 (reports) to about 30 (short-form videos).
- [ ] Why each example counts as "good" (results, client feedback, conversions). Do not invent results.
- [ ] Where the new output will be used, and by whom

## Procedure
1. **Collect proven examples.** Prefer your own best performers. Then add others' work that is clearly strong. Reason: examples define the target precisely. Done when 5+ examples are in one folder, each with its "why good" noted.
2. **Decompose.** Have the agent analyze every example the same way: structure, sections, length, tone, visual and motion patterns, and what each part does for the reader. For video, analyze transcript plus frames. Done when there is one comparison table across all examples.
3. **Separate the pattern from the copy.** List the patterns shared by most examples. Note what varies. Never copy wording, assets or branding. Done when there is a pattern list with "always / usually / optional" labels.
4. **Build the skill or template from the patterns.** Write it so a fresh agent could produce the output with no other context. Done when the SKILL.md or template exists.
5. **Test against the examples.** Produce 1-2 new outputs and compare them side by side with the originals. Revise the skill where they fall short. Done when a reviewer cannot easily tell the new output's quality apart from the examples, or the gaps are listed.

## Decision rules
- Fewer than 5 examples: proceed, but label the skill low confidence and add examples later.
- Examples disagree on a pattern: keep it optional; do not force one style.
- No examples exist: write a short spec by hand instead. This method needs examples.
- Examples belong to a competitor: learn the pattern only. Do not reuse their text or assets.

## Output template
```
Examples used: N (list, with why each is good)
Shared patterns: always / usually / optional
Skill/template: path
Test run: output vs. examples - gaps found
```

## Common mistakes
- Describing the goal in words when you could just show examples.
- Using weak or unproven examples.
- Copying an example instead of learning its pattern.
- Skipping the side-by-side test.
