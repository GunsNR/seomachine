# Design brief template

Fill this from what you can actually see. Mark every line as **stated** (the case
study says so, e.g. a style-guide frame lists the font or hex) or **observed**
(your reading of the screens). Case studies very often include a style-guide
frame — find it first; it turns guesses into facts.

## 1. Source
- URL / files, date captured, number of frames looked at
- Which frames were screens vs. process (personas, wireframes, research)

## 2. Mood in one line
What the design is trying to feel like, in the designer's words if they say it.

## 3. Colour
| Role | Hex | Stated / observed | Where it appears |
|---|---|---|---|
| Background | | | |
| Surface (cards) | | | |
| Ink (body text) | | | |
| Muted text | | | |
| Primary accent | | | |
| Secondary accents / category tints | | | |
| Danger / alert | | | |
Note any gradients, and how much of each screen is colour vs. neutral.

## 4. Type
- Display face: name if stated; otherwise its classification (geometric sans,
  humanist sans, rounded, soft serif…) and 2–3 Google Fonts that match it
- Body face, same
- Scale: rough sizes of screen title / section title / body / caption
- Weights actually used; letter-spacing on headings (tight? loose?)

## 5. Shape and depth
- Corner radii: cards, buttons, inputs, sheets (small / medium / pill)
- Borders vs. shadows vs. flat fills; shadow softness
- Icon style: line or filled, stroke weight, rounded ends?
- Illustration style, if any (describe; do not copy the artwork)

## 6. Layout and density
- Spacing rhythm (tight / airy), screen margins, card padding
- Grid: single column, 2-up tiles, carousels
- How much fits above the fold on the home screen

## 7. Components worth adopting
For each: what it is, what it looks like, why it works for this product.
(Home tiles, check-in cards, progress rings, mood pickers, bottom sheets…)

## 8. Navigation
Tab bar? How many tabs, labels, icon + label? Top app bar? Where do secondary
actions live? How does it handle the emergency / primary action?

## 9. Mapping onto the target UI
| Target token or component | Current value | New value | Why |
|---|---|---|---|
Keep the target's own content, voice and information architecture. Adopt the
reference's *system* (palette roles, type, shape, density, patterns), not its
artwork, screenshots or copy.
